Command 01 — board

Kanban Board

What it is: a 4-column board — Backlog, Todo, In Progress, Done — with one column per field you're tracking, prefilled from a real curriculum instead of a blank list.

Why mtdo has it: a to-do list without sequencing just becomes a pile. Cards claimed out of Backlog always land on Todo first, never straight to In Progress — so "what am I doing today" stays a real decision, not a scroll through everything at once.

How to use it: start each day by clearing Todo before pulling from Backlog. If Done is empty by evening, that's the signal to open Focus Mode next, not to add more cards.

Command 02 — focus

Focus Mode

What it is: one key hides the board and stats, auto-starts a 45/10 pomodoro, and surfaces only the Learning Coach and AI panel for whatever's in progress.

Why mtdo has it: the board is for deciding what to do; Focus Mode is for actually doing it. Nothing running gets stopped when you leave it — press f again and it's exactly where you left it.

How to use it: pull one card into Focus Mode and stay there until the pomodoro ends, not until you feel done — the timer, not your mood, decides when a session's over.

Command 03 — coach dsa / hint

Learning Coach

What it is: generates a real DSA or SQL problem for whatever's in progress, then rations hints one at a time — never the algorithm outright.

Why mtdo has it: reading a solution and understanding it aren't the same skill as producing one under pressure. Hints force you to keep trying before you're handed the shortcut.

How to use it: type hint in the box on the left — try each one before asking for the next. Full coaching notes only unlock after you actually solve it in the Practice Lab, below.

Command 04 — ai <message>

AI Assistant

What it is: an embedded panel that already knows the task, field, and generated problem you're on — you never have to explain context before asking a question.

Why mtdo has it: it's instructed once, permanently: discover-before-explain, progressive hints, never the answer first. Try asking it to just solve it — see what happens on the left.

How to use it: choose its backend once (Claude Code, a local Ollama model, or a direct API chat) — the panel remembers your choice, and you don't re-decide every session.

Command 05 — lab / run / review / fix

Practice Lab

What it is: real execution — Python, Java, C, C++, SQL against a real sqlite3 database — pre-loaded with a deliberately buggy attempt at whatever the coach generated.

Why mtdo has it: review gets you a nudge toward the bug, not the fix; fix only reveals the corrected approach once you ask. The gap between "runs" and "correct" is the actual lesson.

How to use it: run the buggy version first and see it fail quietly (wrong output, not a crash) — that's the real trap this problem is teaching.

Command 06 — crm

Career CRM

What it is: Applied → OA → Interview → Offer, one pipeline for every application, populated automatically when you run the job-switch or college-application setup persona.

Why mtdo has it: a job search scattered across a spreadsheet, an inbox, and memory loses track of where things actually stand. One pipeline, always visible from the same session as your prep.

How to use it: advance a company the moment its status actually changes — the CRM is only useful if it's more current than your memory, not a weekly cleanup chore.

Shown here is the real, genuinely empty CRM screen on a fresh profile — no applications faked in.

Command 07 — vault [search <term>]

Knowledge Vault

What it is: a second brain, separate from any single task — searchable notes on system design, behavioral prep, SQL internals, whatever you've picked up along the way.

Why mtdo has it: insight from three weeks ago is only useful if it resurfaces when it's relevant again — not buried in a chat history or a notes app you stopped opening.

How to use it: write the note the moment something clicks, in your own words — search it here right before an interview instead of re-deriving it from scratch.

Shown here is the real, genuinely empty Vault on a fresh profile — no notes faked in.

Command 08 — keys

Pomodoro & Streaks

What it is: a 45/10 pomodoro auto-starts the moment you enter Focus Mode; streaks and a GitHub-style heatmap track whether you actually showed up, day over day.

Why mtdo has it: "I studied a lot this week" is a feeling. A heatmap is proof — or proof it didn't happen, which is exactly the version you need to see.

How to use it: don't chase a perfect streak — chase a heatmap with no week-long gaps. One missed day resets nothing; a pattern of them means the plan itself needs to change.

Command 09 — music

Music, Without Leaving

What it is: universal now-playing controls for whatever's already going — YouTube Music in a browser tab, Apple Music, Spotify, anything — plus one Spotify-specific shortcut: paste a playlist/album/track link and it plays immediately, no need to open Spotify's own window to find it.

Why mtdo has it: this is the actual thesis of the whole app — the thing that breaks a focus session usually isn't the studying, it's switching screens to change a song. So the controls live right inside Focus Mode, next to the task and the coach, not in a separate app you have to alt-tab to.

How to use it: start a playlist before you press f for Focus Mode, then never touch the source app again for the whole session — skip, pause, and volume from here.

Command 10 — youtube <url>

YouTube → Notes & Quiz

What it is: paste a captioned tutorial link and the AI turns its transcript into two things — real study notes, and 5–8 active-recall questions with no answers given — saved to the Knowledge Vault, yours to edit.

Why mtdo has it: the "tutorial rabbit hole" is real — watching a second and third video on the same topic while quietly assuming the first one landed. Recognizing an explanation isn't the same as being able to produce it; the questions exist to expose that gap before you move on.

How to use it: paste the link on the left, then try answering the questions yourself before checking anything — if you can't, that's the real signal to rewatch, not a vague feeling that you should.

Command 11 — profile

Password-Protected Profiles

What it is: separate, fully isolated profiles — each its own goals and history — for a shared machine, or for splitting your own life into tracks (DSA grind, college applications, a friend's plan). Any profile can optionally be locked with a real password.

Why mtdo has it: a password on a profile here means real local encryption, not a UI lock — the data key is wrapped under your password AND, separately, a one-time recovery code shown once at creation. Either unlocks it independently; nothing is ever stored anywhere that alone could decrypt your data, and nothing leaves your machine.

How to use it: write down the recovery code the moment it's shown — it's the only way back in if you forget the password, and mtdo genuinely never stores it.

Get it running

$ install

Recommended — handles prerequisites for you

$ git clone https://github.com/mukund1312/mtdo.git
$ cd mtdo
$ ./install.sh

checks git, Python 3.10+, sqlite3 (and Xcode Command Line Tools on macOS) up front, with a specific fix for whichever's missing — and sets up its own .venv rather than touching your system Python.

Already have everything installed

$ pip install -e .

from a clone of the repo, then just run mtdo — first run auto-creates ~/.mtdo/config.yaml from the demo plan.
